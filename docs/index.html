System design

Clear boundaries, short-lived trust

The browser never reads authentication tokens. The Go API verifies every request, PostgreSQL owns durable identity state, and Redis handles short-lived security decisions.

WebAuthn flow

Passkeys without hidden magic

The authenticator keeps private key material. The application stores public credentials and validates origin-bound signatures through short-lived, single-use ceremonies.

Begin ceremony

The API creates challenge options and stores ceremony state in Redis with a five-minute TTL. Passwordless login uses an opaque ceremony ID because the user is not known yet.

Verify locally

The browser invokes the platform authenticator or security key. A fingerprint, device PIN, or hardware touch verifies the user without exposing biometric data to the application.

Validate and issue

The backend validates RP ID, origin, challenge, signature, user handle, and counter. The ceremony is consumed once, then secure httpOnly session cookies are issued.

Defense in depth

Controls that reinforce each other

The platform combines cryptographic proof, constrained sessions, explicit authorization, and security telemetry instead of relying on one perimeter check.

Ed25519 Session Tokens

One-minute EdDSA access tokens stay in httpOnly cookies while opaque refresh tokens rotate through database-backed sessions.

Refresh-Reuse Detection

Replaying a rotated refresh token is treated as possible theft and revokes the account's active session family.

Phishing-Resistant Passkeys

Origin-bound WebAuthn credentials provide passkey MFA and discoverable passwordless login with required user verification.

DPoP-Bound M2M Tokens

Service-account tokens bind to a client public key and require signed proof of possession on protected requests.

Step-Up Authorization

Sensitive administrator actions require a recent MFA marker in addition to the correct role and permission.

Runtime Session Policy

Idle limits, absolute limits, concurrent-session caps, and progressive lockouts are configurable without redeployment.

CSRF & Browser Hardening

Double-submit CSRF tokens, strict cookies, CSP, HSTS, and restrictive browser policies reduce common web attack paths.

Fine-Grained RBAC

Roles map to explicit permissions for user, audit, settings, and service-account operations.

Security Observability

Synchronous audit events and Prometheus metrics make authentication behavior and administrative changes inspectable.
