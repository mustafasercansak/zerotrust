Global System Security Settings

Administrator-level dashboard to configure critical security policies dynamically. Exposes control inputs (secured via Step-Up MFA verification) for the following platform policies:

Max Concurrent Sessions max_sessions_per_user
Cap on active sessions allowed per account (1–20, default: 5). Evicts oldest sessions first.
Password Complexity Level password_complexity
Enforce Low (min 6 chars), Medium (min 8, letter/digit), or Strong (min 8, mixed case/digit/symbol) policies.
Max Login Attempts max_login_attempts
Lockout threshold (1–20, default: 5). Failures trigger progressive 1/5/30-minute lockouts.
Global Two-Factor Auth (2FA) global_mfa_required
Enforce MFA setup and challenge verification globally for all active logins.
Session Idle Timeouts session_idle_timeout_seconds
Inactivity windows. User range 60–3600s (default: 300s); Admin range 60–1800s (default: 180s).
Absolute Session Timeout session_absolute_timeout_seconds
Hard cap on overall session duration. Range 1800–172800s (default: 28800s / 8 hours).

Zero Trust Security Principles

Double Token Auth Model

Access tokens are short-lived (1-minute TTL) ES256 ECDSA signed JSON Web Tokens (JWT) kept in secure, httpOnly cookies. Rotation relies on opaque database-backed refresh tokens.

Token Reuse Protection

If an older rotated refresh token is re-submitted, the system flags it as a potential hijack attempt, immediately invalidates all active sessions for that user, and registers a security alert.

Runtime Session Policies

System settings govern session lifecycles dynamically: enforcing idle timeout windows (e.g. 5 minutes for regular users, 3 minutes for admins) and hard absolute caps (8 hours).

Observable Audit Logging

Every critical security event (login, token rotation, session revocation, MFA setup, role change) writes synchronously to a database audit log, feeding an exported Prometheus metric counter.

Step-Up MFA Gates

Sensitive user administration and token-management activities require recent (within 10 minutes) multi-factor authentication. If expired, an inline TOTP challenge is triggered.

Machine-to-Machine Auth

Secure client_credentials flow for service accounts. Emits scope-bounded access tokens, permitting automated API-driven integrations with fine-grained access policies.
